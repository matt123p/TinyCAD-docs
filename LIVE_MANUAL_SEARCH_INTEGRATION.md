# Live Manual Search Integration

This manual site publishes the search index that powers the in-page search UI. Another app or website can reuse that same index directly from the live manual site and keep results in sync with each deployment.

## Multilingual v4 indexes

Use `/assets/manual-index-v4-<language>.json`, where `<language>` is `en`, `nl`,
`fr`, `es`, `de`, `it`, `ja`, `pl` or `zh-CN`. Each payload identifies its `version`,
`language` and `engine`; verify these before displaying results. Its document
URLs point to that language's pages. Generate these assets with
`npm run build:search-index`, which first prepares current translations/fallbacks.

For `engine: "lunr"` (English), load `indexData` with Lunr. For
`engine: "unicode-substring"` (translated pages), search the `title` and `content`
fields after Unicode NFKC normalization and locale-aware lowercasing; require all
query terms and rank title matches first. This also supports Japanese and Chinese
without imposing English stemming. See `translatedMatches` in
`docs/assets/manual-search.js` for the exact matcher. The site bundles Lunr at
`/assets/lunr.min.js`; search does not require a CDN.

The legacy version-only URLs below remain English/v3 compatibility endpoints.
They are regenerated alongside the language-specific assets on every build.

## What is published

The build step generates these versioned search assets:

- `/assets/lunr-index-v3.json`
- `/assets/lunr-index-v4.json`
- `/assets/lunr-index-v3.js`
- `/assets/lunr-index-v4.js`

The recommended integration target is the JSON payload. Example:

```js
{
  indexData: { /* Lunr serialized index */ },
  docs: [
    {
      id: 0,
      url: "/v4/Getting-started/",
      title: "Getting started",
      snippet: "First 220 characters of searchable content..."
    }
  ]
}
```

The payload is generated by [scripts/build-search-index.js](scripts/build-search-index.js). The current search behavior on the manual site lives in [docs/assets/manual-search.js](docs/assets/manual-search.js).

## Recommended approach

For a browser-based app, the simplest approach is:

1. Load Lunr in your app.
2. Fetch the manual index JSON from the live manual site.
3. Rebuild the Lunr index from `indexData`.
4. Search locally in the client.
5. Prefix each result URL with the manual site base URL before opening it.

This keeps search live without needing a separate API service.

## Implementation steps

## 1. Pick the manual base URL

Set the base URL for the deployed manual site. Example:

```js
const MANUAL_BASE_URL = 'https://docs.tinycad.net/';
```

If the manual is hosted under a subpath, include the subpath:

```js
const MANUAL_BASE_URL = 'https://www.example.com/tinycad-manual/';
```

## 2. Install or load Lunr

Use Lunr `2.3.9` to match the generated index format.

Browser bundle:

```bash
npm install lunr@2.3.9
```

Then:

```js
import lunr from 'lunr';
```

If your app does not bundle dependencies, you can also load Lunr from a CDN the same way the manual site does.

## 3. Fetch the live index JSON

Use the version that matches the manual content you want to search.

```js
async function loadManualIndex(version) {
  const assetUrl = new URL(`assets/lunr-index-${version}.json`, MANUAL_BASE_URL).toString();
  const response = await fetch(assetUrl, {
    method: 'GET',
    headers: {
      Accept: 'application/json'
    }
  });

  if (!response.ok) {
    throw new Error(`Failed to fetch manual search payload for ${version}: ${response.status}`);
  }

  const payload = await response.json();
  if (!payload || !payload.indexData || !Array.isArray(payload.docs)) {
    throw new Error(`Manual search payload for ${version} is missing or invalid`);
  }

  return payload;
}
```

## 4. Recreate the Lunr index locally

```js
async function createManualSearch(version) {
  const payload = await loadManualIndex(version);
  const index = lunr.Index.load(payload.indexData);
  const docsById = new Map(payload.docs.map((doc) => [String(doc.id), doc]));

  return {
    search(query) {
      const matches = searchManualIndex(index, query);

      return matches.map((match) => {
        const doc = docsById.get(String(match.ref));
        if (!doc) {
          return null;
        }

        return {
          title: doc.title,
          snippet: doc.snippet,
          relativeUrl: doc.url,
          absoluteUrl: new URL(doc.url, MANUAL_BASE_URL).toString(),
          score: match.score
        };
      }).filter(Boolean);
    }
  };
}
```

## 5. Mirror the manual site's search behavior

The manual search does two passes:

1. Try a direct Lunr search with the full query.
2. If that returns nothing, tokenize the query and run a fallback query using exact and trailing-wildcard matches.

This is the same logic the manual site currently uses:

```js
function getNormalizedTerms(index, queryText) {
  if (!index || !index.searchPipeline) {
    return queryText
      .trim()
      .split(/\s+/)
      .map((term) => term.trim())
      .filter(Boolean);
  }

  return index.searchPipeline.run(lunr.tokenizer(queryText))
    .map((token) => token.toString())
    .filter(Boolean);
}

function searchManualIndex(index, queryText) {
  const searchText = queryText.trim();
  if (!searchText) {
    return [];
  }

  try {
    const directMatches = index.search(searchText);
    if (directMatches.length) {
      return directMatches;
    }
  } catch {
    // Ignore parse errors and continue to fallback matching.
  }

  const terms = getNormalizedTerms(index, searchText);
  if (!terms.length) {
    return [];
  }

  return index.query((query) => {
    terms.forEach((term) => {
      query.term(term, { boost: 20 });
      query.term(term, {
        wildcard: lunr.Query.wildcard.TRAILING,
        boost: 10,
        presence: lunr.Query.presence.REQUIRED
      });
    });
  });
}
```

## 6. Hook it into your app

Example:

```js
let manualSearchPromise;

function getManualSearch(version = 'v4') {
  if (!manualSearchPromise) {
    manualSearchPromise = createManualSearch(version);
  }

  return manualSearchPromise;
}

async function searchManual(query) {
  const manualSearch = await getManualSearch('v4');
  return manualSearch.search(query).slice(0, 10);
}

async function onSearchManualMenuClick() {
  const query = window.prompt('Search the manual');
  if (!query) {
    return;
  }

  const results = await searchManual(query);
  console.log(results);
}
```

## Version selection

Use:

- `v4` for the current web/manual content.
- `v3` only if you explicitly want legacy manual content.

If your app needs both, keep one cache per version.

## Caching guidance

The search payload is static per deployment, so cache it aggressively in memory.

Recommended minimum behavior:

- Load the index once per app session.
- Reuse the loaded Lunr index for all subsequent searches.
- Limit displayed results to 10 to match the manual site.

If you want persistent caching across launches, you can store the raw payload in local storage or IndexedDB. On the next app launch, use the cached payload first and refresh it in the background.

## Error handling

Handle these cases:

- Lunr script failed to load.
- Manual index JSON failed to load.
- Payload shape changed or is invalid.
- Query string cannot be parsed by direct Lunr search.

If any of those happen, show a fallback message such as: `Manual search is temporarily unavailable.`

## Cross-origin note

If the calling app is running in a browser on a different origin, `fetch()` requires the manual host to allow cross-origin requests for these JSON files.

Expected request URL format:

```js
const response = await fetch('https://docs.tinycad.net/assets/lunr-index-v4.json');
const payload = await response.json();
```

If the browser blocks this request, verify that `https://docs.tinycad.net/assets/lunr-index-v4.json` is returning an `Access-Control-Allow-Origin` header that covers the caller's origin. If not, you have two options:

- Enable CORS on the manual host.
- Proxy the JSON through the calling app's own backend.

## Summary

If you want the other app to use the manual search live:

1. Use Lunr `2.3.9`.
2. Fetch `https://docs.tinycad.net/assets/lunr-index-v4.json`.
3. Rebuild the Lunr index from `indexData`.
4. Search client-side using the fallback query logic above.
5. Open results by resolving each `doc.url` against the manual site's base URL.
