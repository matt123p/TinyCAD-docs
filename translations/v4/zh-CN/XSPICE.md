# XSPICE 与数字仿真
{: #xspice-and-digital-simulation}

XSPICE 通过代码模型和由模拟求解器协调的事件驱动仿真系统扩展了 ngspice。它适用于门电路、时钟、存储器以及模拟/数字混合系统。有关上游架构，请参阅官方 [XSPICE 概述](https://ngspice.sourceforge.io/xspice.html)。

**TinyCAD Desktop 支持 XSPICE，浏览器版本不支持。** Desktop 的原生引擎包含随附的代码模型库。

*查看已保存的结果：* 浏览器仍可打开包含先前 XSPICE 采集数据的图纸。这使您可以检查已保存的结果；运行仿真则需要 Desktop。

## 选择合适的逻辑模型
{: #choose-the-right-logic-model}

| 方法 | 工作原理 | 适用场景 |
| --- | --- | --- |
| 随附的**数字逻辑**和**功能模块** | 具有已配置电源和阈值的便携式模拟行为 SPICE 模型 | 浏览器和 Desktop 中的系统级分析 |
| XSPICE 教程符号/模型 | 事件驱动逻辑、延迟、存储以及显式模拟/数字桥接 | Desktop 原生混合信号仿真 |

因此，外观相似的门电路可能具有不同的建模约定。不要仅凭外观就用一种替代另一种。两种方法都不能让 ESP32、Raspberry Pi 或 Arduino 电路板图片执行固件。TinyCAD 集成并非通用 HDL 或嵌入式软件执行环境。

## 模拟和数字节点
{: #analogue-and-digital-nodes}

模拟节点承载连续变化的电压/电流。数字事件节点承载状态。**ADC 桥接器**应用阈值，将模拟输入映射为数字状态；**DAC 桥接器**则将数字状态映射回模拟输出电平。这些桥接器描述的是仿真器域之间的转换，不一定是完整的物理 ADC/DAC 器件。

检查阈值、电源电平和输出负载。处于有效逻辑阈值之间的电压可能产生未知状态。存储器可能会一直处于未知状态，直到时钟/复位条件将其确定。未知状态是有用的诊断信息；将其替换为假定的 0 可能会掩盖真实的时序或初始化问题。

传播延迟会使时间变得重要。即使静态真值表看起来正确，路径延迟不同的门电路也可能产生毛刺。选择足以解析模拟响应和要测量时序的瞬态最大步长。不要仅根据粗略显示推断事件延迟。

## 学习数字仿真课程
{: #run-the-digital-course}

1. 在 Desktop 中选择 **文件 → 打开示例 → XSPICE 与数字教程**。
2. 打开课程中指定名称的图纸。图纸中包含符号、代码模型声明和保留的结果。
3. 通过 **视图 → 查看说明** 阅读讲解，并选择其仿真工作表。
4. 选择 **运行** 进行新的原生数据采集，然后将状态和时序与课程内容进行比较。
5. 更改阈值、延迟、复位或时钟时序之前，先保存副本。

[六章 XSPICE 教程](../XSPICE-Tutorial/)涵盖桥接器和首次运行、门电路与真值表、毛刺、触发器、计数器以及混合信号滤波。教程包含电路图、求解器绘图和可下载的配套资料。

## 上游参考资料
{: #upstream-reference}

有关代码模型语法和支持的端口，请参阅官方 [ngspice 文档和手册](https://ngspice.sourceforge.io/docs.html)。[XSPICE HOWTO](https://ngspice.sourceforge.io/xspicehowto.html)介绍代码模型开发，而 [XSPICE 用法](https://ngspice.sourceforge.io/xspiceusage.html)则提供更多示例和背景信息。这些资源介绍的是 ngspice 整体。TinyCAD 使用其随附的原生模块；它不会通过图纸附件加载任意用户提供的编译代码模型。
