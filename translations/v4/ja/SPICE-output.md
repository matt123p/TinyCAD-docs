# SPICEモデルとネットリスト出力
{: #spice-models-and-netlist-output}

TinyCADは、[統合ngspiceシミュレーション](../Simulation/)と、外部シミュレーター向けのSPICEネットリストのエクスポートの両方をサポートしています。どちらも、コンポーネントのSPICEテンプレートとピンマッピングに依存します。シンボルの外観だけでは、その電気的な動作はわかりません。

TinyCADにすでに含まれているモデルを選ぶ場合は、[同梱SPICEモデル](../Bundled-SPICE-Models/)から始めてください。

## モデル、テンプレート、ピン順序
{: #models-templates-and-pin-order}

抵抗器にはネイティブのSPICE素子を使用できます。トランジスタでは`.model`が必要な場合があり、より複雑なデバイスでは`.subckt`を使用できます。配置したシンボルのSPICE設定では、その物理ピン番号をモデルが想定する端子に対応付けます。シンボルのプロパティにある **SPICE** タブを確認してください。インスタンス属性でシンボルの既定値を上書きできます。

テンプレートでは次を使用します。

- 指定したTinyCADピン番号に接続されたネットには **`%(pin)`**。
- コンポーネント属性には **`$(attribute)`**。
- テンプレートのSPICE素子プレフィックスが保持されるよう、特別に処理されるリファレンスのサフィックスには **`refnum`**。

たとえば、抵抗器のテンプレートは次のようになります。

```text
R$(refnum) %(1) %(2) $(Value)
```

リファレンスR3、ネット7と9、Value `10k`の場合、次のように生成されます。

```spice
R3 7 9 10k
```

基となるモデルテンプレート属性は **`$$SPICE`**、プロローグテキストは **`$$SPICE_PROLOG`** です。テンプレートではピンの順序を変更できます。回路図のピン1がSPICEの第1端子だと思い込まないでください。BJT素子が想定する順序は **コレクタ、ベース、エミッタ** です。シンボルでベースが1、エミッタが2、コレクタが3と番号付けされている場合、テンプレートではその順序で`%(3) %(1) %(2)`を代入する必要があります。サブサーキットでは、その`.subckt`行で宣言された順序を使用します。この順序はデバイスのパッケージのピン順序と異なる場合があります。

実際のシンボルとモデルを併せて確認してください。電源ピン、非表示ピン、トランジスタのバリエーション、オペアンプのモデルは、不一致の原因になりやすい項目です。汎用の741風の動作モデルは、メーカー認定の741マクロモデルと同等ではありません。

## 統合シミュレーションでモデルを使用する
{: #use-a-model-in-integrated-simulation}

1. [同梱モデル](../Bundled-SPICE-Models/)から始めるか、シンボルに適切なカスタムテンプレートを追加します。ピンの割り当てがモデルの端子順と一致していることを確認してください。
2. TinyCADはリンクされた同梱モデルを自動的に解決します。カスタムモデルで外部テキストが必要な場合は、**設定 (Setup) → SPICEモデル (SPICE models)** を使い、`part.lib`、`part.cir`、または`part.mod`のような論理ファイル名で添付します。
3. それらの添付ファイルを通じて、`.include`および`.lib`の依存関係を解決します。必要な定義を図面とともに保持するため、図面を保存してください。
4. グラウンド **0** を接続し、**設定 (Setup)** で解析を設定してから、実行して診断結果を確認します。

管理されたエンジンは、ウェブサイトからモデルを取得したり、コンピューター上の任意の絶対パスを読み込んだりしません。依存関係は明示的に指定してください。また、任意のシェルコマンド、`.control`スクリプト、スタートアップファイル、外部から提供されたネイティブモジュール、またはファイルベースのデバイス依存関係も実行しません。シミュレーター固有の構文を使うベンダーモデルは、調整が必要な場合があります。「SPICE互換」であっても、方言が同一であるとは限りません。

TinyCADの統合シミュレーションシートが解析コマンドと最終`.end`を管理します。**従来のRUNシンボルは不要です。** エクスポート向けの図面を適応する場合は、古い解析設定を設定 (Setup) に移し、従来のRUNシンボルを削除してください。残りのコンポーネント属性から解析文と`.end`を削除してください。統合されたコンポーネントテンプレートの経路では、これらのコマンドは拒否されます。

ベンダーモデルを再配布する前に、そのライセンスを確認してください。文書化されたピン順、単位、モデルの前提条件、および対応シミュレーターを確認してください。モデリングに関するメモとともに、メーカーのドキュメントを保管してください。

## SPICEネットリストの確認とエクスポート
{: #inspect-and-export-a-spice-netlist}

ネットリストは、デバイスとそれらを接続するノードを記述したテキストです。グラウンドの名前は`0`です。一般的な内容には、モデル／設定の定義、コンポーネント行、解析指示、最後の`.end`が含まれます。次の点を確認してください。

- 各コンポーネントが意図したモデルと値を参照しているか。
- 接続されたピンが想定どおりのネット名を共有しているか。
- 0を含む電源／リターンネットが存在するか。
- 半導体またはサブサーキットの端子順序が正しいか。
- 選択したエンジンで、すべてのモデル定義とインクルードテキストを利用できるか。

統合設定の場合は、**Simulation sheet → Diagnostics → Generate circuit text**を開いて展開されたデックを確認し、次に**Export circuit**を選択して`simulation.cir`を保存します。これには管理対象の解析が含まれ、`.include`を使って別のモデルファイルを参照する場合があります。外部シミュレーターを使用する場合は、指定された場所にこれらのファイルのコピーが必要です。

従来のテンプレートベースのエクスポートでは、ブラウザーのFileメニューまたはDesktop Toolsメニューにある別個の**Generate Spice NetList**コマンドを使用します。これは、PCB向けの[Generate Netlist](../Generate-Netlist/)ダイアログとは別のコマンドです。このコマンドは、参照される同梱定義を埋め込みます。Customテンプレートで使用する外部依存関係を指定し、解析指示と実行指示が外部エンジンに適していることを確認してください。チュートリアル付属の`.cir`ファイルを直接確認することもできます。**TinyCADで`.dzn`図面を開いてください。`.cir`ネットリストはTinyCADの図面ファイルではありません。**

### 従来のエクスポートテンプレート
{: #legacy-export-templates}

エクスポート向けテンプレートシステムでは、インスタンスごとのモデル本体に加えて、シンボルごとのプロローグとエピローグをサポートします。同一のプロローグ／エピローグは重複排除されます。優先度は0から9までです。プロローグは優先度の低い順から高い順に実行され、エピローグは優先度0が最後になるように配置されます。

古い図面では、エクスポートされたデックの解析指示と終了指示をプロローグ／エピローグで指定する、ピンのない**RUN**シンボルを使用している場合があります。これはエクスポート時の慣例であり、統合SimulationシートにRUNを追加する指示ではありません。エクスポートしたファイルを別のシミュレーターで実行する前に、これらの文を確認してください。

### 条件付きテンプレート
{: #conditional-templates}

エクスポート向け／Customテンプレートでは、次の条件付き形式がサポートされています。

```text
?( defined(attribute), true text, false text )
?( not_defined(attribute), true text, false text )
?( empty(attribute), true text, false text )
?( not_empty(attribute), true text, false text )
?( connected(pin), true text, false text )
?( not_connected(pin), true text, false text )
```

条件文は入れ子にできます。複雑なテンプレートはソーステキストだけで判断せず、展開されたデックを確認してください。

## 数値表記と移植性
{: #numerical-notation-and-portability}

SPICEテキストでは、**`M` はミリを表し**、`m` と同じです。メガには **`Meg`** を使用してください。`1k`、`100n`、`10u` は一般的な値です。シミュレーターで指定されていないデフォルト値に頼らず、モデルパラメーターと参照を明示してください。

ngspiceの外部コマンドライン向けドキュメントは、TinyCADの統合エンジンよりも広範な環境を対象としています。要素の構文、モデル、解析、互換性に関する注意事項については、公式の[ngspiceドキュメント](https://ngspice.sourceforge.io/docs.html)および[ユーザーマニュアル](https://ngspice.sourceforge.io/docs/ngspice-manual.pdf)を参照してください。エンジン、シンボル、ネットリストについて具体例を交えた説明は、[TinyCADによるSPICEの実装方法](../SPICE-Tutorial-11/)に進んでください。
