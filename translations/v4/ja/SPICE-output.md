# SPICE出力
{: #spice-output}

TinyCAD v4のSPICEサポートはv3と同じように動作します。TinyCADはシンボルレベルのテンプレートを使用して、回路図からSPICEテキストファイルを生成します。

## SPICEの用途
{: #what-spice-is-used-for}

SPICE（Simulation Program with Integrated Circuit Emphasis）は、回路シミュレーション用の形式およびツールの総称です。SPICEシミュレーターを使うと、ハードウェアを製作する前に、たとえば次のような回路の動作をテストできます。

- DC動作点とバイアス条件
- 過渡（時間領域）応答
- AC／周波数応答
- パラメーター掃引と「もしも」の解析

TinyCAD自体はシミュレーションを実行しません。代わりにSPICEファイルを書き出し、選択したSPICEエンジンで実行します。

## SPICEファイル形式と全体構成
{: #spice-file-format-and-general-layout}

SPICEエンジンによって細部は多少異なりますが、ほとんどのSPICEファイルは同じような全体構成になっています。

1. ヘッダー／コメント（任意）
2. デバイス／モデルのインクルードと定義
3. 回路素子の行（コンポーネントのインスタンスごとに1行）
4. 解析／制御コマンド
5. 終了マーカー（一般的には`.end`）

実際には、書き出されたファイルは通常、次の内容で構成されます。

- ファイルの先頭にある「Setup」テキスト（モデル、インクルード、オプション）
- 生成されたコンポーネントと接続されたネットを含む本体
- ファイルの末尾にある「Run」または解析のテキスト

TinyCADのSPICE生成機能は、この構成に直接対応するように設計されています。

## TinyCADによるSPICEの生成方法
{: #how-tinycad-generates-spice}

TinyCADでは、SPICEに対応した各シンボルに文字列テンプレートを使用します。各シンボルには、次の内容を定義できます。

- **モデルテンプレート**: 回路図内のそのコンポーネントのインスタンスごとに挿入
- **プロローグテンプレート**: ファイルの先頭付近に、コンポーネントの種類ごとに1回挿入
- **エピローグテンプレート**: ファイルの末尾付近に、コンポーネントの種類ごとに1回挿入

これらのフィールドは、シンボルライブラリエディターのシンボルプロパティ（SPICEタブ）から開きます。

### テンプレートの展開
{: #template-expansion}

テンプレートには、次のものを含めることができます。

- ピン／ネットの置換用`%(pin)`
- シンボル属性の置換用`$(attribute)`

抵抗器のモデルテンプレートの例:

`R$(refnum) %(1) %(2) $(NAME)`

抵抗器のインスタンスの参照名が`R3`で、ネット`7`と`9`の間に接続され、`NAME=10K`の場合、TinyCADは次のように書き出します。

`R3 7 9 10K`

`refnum`は特別に処理されるため、テンプレート内のSPICEデバイス文字がそのまま保持されます。

### プロローグ／エピローグの順序と重複排除
{: #prologueepilogue-order-and-deduplication}

- プロローグとエピローグは、同一の場合に重複排除されます
- それぞれに優先度があります（`0`～`9`）
- プロローグは優先度の低いものから高いものへ順に書き出されます
- エピローグは、優先度`0`のものがファイルの最後に現れるように書き出されます

これにより、セットアップと解析のテキストがどこに表示されるかを制御できます。

## SPICE書き出しに必要な回路図の設定
{: #required-schematic-setup-for-spice-export}

有効なSPICEファイルを生成するには、図面に次のものを含める必要があります。

- シミュレーション対象の回路に使用するSPICE対応シンボル
- 特別な**RUN**シンボル
- **0**という名前のネット（SPICEのグラウンド）

### RUNシンボル
{: #run-symbol}

RUNシンボルは、ピンとモデルテンプレートを持たない通常のTinyCADシンボルですが、シミュレーション制御文を挿入するためのプロローグ／エピローグテキストを持ちます。

RUNのプロローグとエピローグの優先度を`0`に設定すると、そのテキストが生成ファイルの先頭と末尾に表示されます。

シミュレーション回路ごとにRUNシンボルを1つ使用してください。

### `0`ネット
{: #the-0-net}

SPICEでは、グラウンドをネット`0`にする必要があります。

TinyCADでは、次のいずれかを使って接続に`0`という名前を付けます。

- ネットラベル
- 値が`0`の電源シンボル

## SPICE出力の作成
{: #creating-the-spice-output}

シンボル、RUNノード、および`0`ネットを配置したら、TinyCADのUIにあるSPICE書き出しコマンドを使ってSPICE出力を生成します。

実行時の動作はRUNシンボルのテンプレートで制御することを想定しているため、書き出しオプションは意図的に最小限に抑えられています。

## 高度なテンプレート条件式
{: #advanced-template-conditionals}

より高度なシンボルでは、条件式を使用できます（動作はv3と同じ）。次の条件をテストできます。

- 属性が存在する／存在しない
- 属性が空である／空でない
- ピンが接続されている／接続されていない

条件式の構文:

- `?( defined(attributename), true string, false string )`
- `?( not_defined(attributename), true string, false string )`
- `?( empty(attributename), true string, false string )`
- `?( not_empty(attributename), true string, false string )`
- `?( connected(pinnumber), true string, false string )`
- `?( not_connected(pinnumber), true string, false string )`

条件式は入れ子にできます。
