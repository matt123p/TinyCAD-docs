# SPICEモデルとネットリスト出力
{: #spice-models-and-netlist-output}

TinyCADは、[統合ngspiceシミュレーション](../Simulation/)と、外部シミュレーター向けのSPICEネットリストのエクスポートの両方をサポートしています。どちらも、コンポーネントのSPICEテンプレートとピンの割り当てに依存します。シンボルの外観だけでは、その電気的な動作はわかりません。

## モデル、テンプレート、ピンの順序
{: #models-templates-and-pin-order}

抵抗器には、ネイティブSPICE素子を使用できます。トランジスターには`.model`が必要な場合があり、より複雑なデバイスには`.subckt`を使用できます。配置したシンボルのSPICE設定では、物理ピン番号をモデルが想定する端子に対応付けます。シンボルのプロパティにある**SPICE**タブを確認してください。インスタンス属性でシンボルの既定値を上書きできます。

テンプレートでは次のものを使用します。

-  **`%(pin)`** は、指定したTinyCADピン番号に接続されているネットを表します。
-  **`$(attribute)`** は、コンポーネント属性を表します。
-  **`refnum`** は、テンプレートのSPICE素子接頭辞を保持するために特別に処理される参照接尾辞です。

たとえば、抵抗器のテンプレートは次のようになります。

```text
R$(refnum) %(1) %(2) $(NAME)
```

参照名R3、ネット7と9、NAME `10k`の場合、次のように出力されます。

```spice
R3 7 9 10k
```

基になるモデルテンプレート属性は **`$$SPICE`** 、プロローグテキストは **`$$SPICE_PROLOG`** です。テンプレートではピンの順序を入れ替えられます。回路図のピン1がSPICEの最初の端子だとは限りません。BJT素子が想定する順序は **コレクタ、ベース、エミッタ** です。シンボルでベースが1、エミッタが2、コレクタが3と番号付けされている場合、テンプレートではその順序で`%(3) %(1) %(2)`を置き換える必要があります。サブサーキットでは、デバイスのパッケージとは異なる場合がある、`.subckt`行で宣言された順序が使われます。

シンボルとモデルを実際に照らし合わせて確認してください。電源ピン、非表示ピン、トランジスターのバリエーション、オペアンプのモデルは、よく不一致の原因になります。汎用の741風動作モデルは、メーカー認定の完全な741マクロモデルではありません。

## 統合シミュレーションでモデルを使用する
{: #use-a-model-in-integrated-simulation}

1. [同梱のシミュレーションライブラリ](../Bundled-Libraries/#libraries-with-simulation-models)にあるモデル付きシンボルから始めるか、カスタムシンボルに適切なSPICEテンプレートを追加します。
2. 各テンプレートが既存の属性と正しいピンを参照していることを確認します。
3. Simulationシートで、必要なモデルの**テキスト**を添付し、添付ファイルにわかりやすいファイル名を付けます。一般的なテキストファイルの拡張子は`.lib`、`.cir`、`.mod`です。
4. 添付ファイルを使って、`.include`と`.lib`の依存関係を解決します。必要な定義は図面と一緒に保管してください。
5. グラウンド**0**を接続し、**Setup**で解析を設定してから、実行し、診断結果を確認します。

管理対象エンジンは、ウェブサイトからモデルを取得したり、コンピューター上の任意の絶対パスを読み込んだりしません。依存関係は明示的に指定してください。また、任意のシェルコマンド、`.control`スクリプト、スタートアップファイル、外部から提供されたネイティブモジュール、ファイル依存デバイスを実行しません。シミュレーター固有の構文を使うベンダーモデルは、変更が必要な場合があります。「SPICE互換」であっても、方言が同一であるとは限りません。

TinyCADの統合Simulationシートが解析コマンドと最終的な`.end`を管理します。 **統合シミュレーションに旧式のRUNシンボルは必要ありません。** エクスポート向けの図面を変換する場合は、古い解析設定をSetupに移し、旧式のRUNシンボルを削除してください。残っているコンポーネント属性から解析ステートメントと`.end`を削除してください。統合コンポーネントテンプレートの経路では、これらのコマンドは拒否されます。

ベンダーモデルを再配布する前に、ライセンスを確認してください。文書化されたピンの順序、単位、モデルの前提条件、対応シミュレーターを確認します。モデリングに関するメモと一緒に、メーカーの資料を保管してください。

## SPICEネットリストを確認してエクスポートする
{: #inspect-and-export-a-spice-netlist}

ネットリストは、デバイスと、それらを接続するノードを記述したテキストです。グラウンドの名前は`0`です。一般的な内容は、モデル／設定の定義、コンポーネント行、解析指示、最後の`.end`です。次の点を確認するとよいでしょう。

- 各コンポーネントが意図したモデルと値を参照しているか。
- 接続されたピンが期待どおりのネット名を共有しているか。
- 0を含め、電源／リターンのネットが存在するか。
- 半導体またはサブサーキットの端子順序が正しいか。
- すべてのモデル定義とインクルードテキストが、選択したエンジンで利用できるか。

統合環境の設定では、**Simulation sheet → Diagnostics → Generate circuit text**を開いて展開後のデッキを確認し、**Export circuit**を選択して`simulation.cir`を保存します。これには管理対象の解析が含まれます。

旧式のテンプレートベースのエクスポートには、ブラウザーのFileメニューまたはDesktop Toolsメニューにある別個の**Generate Spice NetList**コマンドを使用します。これは、PCB向けの[Generate Netlist](../Generate-Netlist/)ダイアログとは別の機能です。エクスポートされる解析／実行指示は、外部エンジンに適したものである必要があります。付属のチュートリアル`.cir`ファイルを直接確認することもできます。**`.dzn`図面はTinyCADで開いてください。`.cir`ネットリストはTinyCADの図面ファイルではありません。**

### 旧式のエクスポートテンプレート
{: #legacy-export-templates}

エクスポート向けのテンプレートシステムでは、インスタンスごとのモデル本体と、シンボルごとのプロローグおよびエピローグをサポートしています。同一のプロローグ／エピローグは重複排除されます。優先度は0から9までです。プロローグは優先度の低い順に実行され、エピローグは優先度0が最後になるように配置されます。

古い図面では、ピンのない**RUN**シンボルを使って、エクスポートしたデッキ用の解析指示と終了指示をプロローグ／エピローグに記述している場合があります。これはエクスポート時の慣例であり、統合SimulationシートにRUNを追加する指示ではありません。エクスポートしたファイルを別のシミュレーターで実行する前に、これらのステートメントを確認してください。

### 条件付きテンプレート
{: #conditional-templates}

エクスポート向け／カスタムテンプレートでは、次の条件付き形式がサポートされています。

```text
?( defined(attribute), true text, false text )
?( not_defined(attribute), true text, false text )
?( empty(attribute), true text, false text )
?( not_empty(attribute), true text, false text )
?( connected(pin), true text, false text )
?( not_connected(pin), true text, false text )
```

条件は入れ子にできます。複雑なテンプレートは、ソーステキストだけで判断せず、展開後のデッキを確認してください。

## 数値表記と移植性
{: #numerical-notation-and-portability}

SPICEテキストでは、 **`M`はミリ** を表し、`m`と同じです。メガには **`Meg`** を使用してください。`1k`、`100n`、`10u`は一般的な値です。シミュレーターで未指定の既定値に頼らず、モデルパラメーターと参照を明示してください。

TinyCADに統合されたエンジンよりも広範な環境については、外部のngspiceコマンドラインのドキュメントを参照してください。要素の構文、モデル、解析、互換性に関する注意事項の詳細は、公式の[ngspiceドキュメント](https://ngspice.sourceforge.io/docs.html)および[ユーザーマニュアル](https://ngspice.sourceforge.io/docs/ngspice-manual.pdf)を参照してください。エンジン、シンボル、ネットリストについて具体例を用いた説明は、[TinyCADにおけるSPICEの実装](../SPICE-Tutorial-11/)を参照してください。
