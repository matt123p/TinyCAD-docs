# 11. TinyCAD における SPICE の実装
{: #how-tinycad-implements-spice}

[前へ: 設計の検討](/v4/SPICE-Tutorial-10/) · [目次](/v4/Simulation-Tutorials/) · [XSPICE コース](/v4/XSPICE-Tutorial-01/)

TinyCAD は回路図エディター、シミュレーション設定、計測器、チャート、
および測定機能を提供します。その基盤となる回路解析エンジンが **ngspice** です。
TinyCAD で実験を描画・設定すると、TinyCAD がそれを SPICE 回路テキストに変換し、
ngspice を実行して、返された結果を表示します。

この章の例は TinyCAD に同梱されています。**Open Example →
SPICE tutorial** を選び、**divider** または **rc-ac** を選択してから、
**Open Drawing** を選びます。デジタルのデモには、**Open Example → XSPICE and digital tutorial →
logic-buffer → Open Drawing** を使用します。チュートリアルやモデルをダウンロードする必要はありません。

## SPICE、ngspice、XSPICE
{: #spice-ngspice-and-xspice}

SPICE では、回路をコンポーネント、接続されたノード、数学的なデバイスモデルとして
記述します。動作点解析では、それらの DC 方程式を解きます。過渡解析では、シミュレーション
時間の経過に伴う挙動を追跡します。AC 解析では、バイアス点を中心に回路を線形化し、
小信号の周波数応答を計算します。したがって、解析の選択は実験の定義の一部です。

ngspice は、Berkeley SPICE を起源とするオープンソースの混合信号回路シミュレーターです。
TinyCAD は、別個のコマンドラインシミュレーターをインストールして実行する必要がないよう、
そのエンジンを同梱しています。このチュートリアルの適格性確認に使用したエンジンは
**ngspice 47** です。実行の **Diagnostics** ビューには、バックエンドとビルドが表示されます。
上流プロジェクトの背景については、[ngspice 公式概要](https://ngspice.sourceforge.io/presentation.html)
を参照してください。

**XSPICE は ngspice に統合された拡張機能**であり、別に起動するアプリケーションではありません。
機能的なアナログブロックや、アナログソルバーと連携してイベントを処理するデジタルロジックなどの
コードモデルを追加します。そのため、同じシミュレーション内でデジタル状態の変化が
アナログ回路に影響を与えることができます。[XSPICE 公式紹介](https://ngspice.sourceforge.io/xspice.html)
では、この違いについて説明しています。

| TinyCAD 環境 | エンジンの実行方法 | 使用する例 |
| --- | --- | --- |
| デスクトップ | 同梱の XSPICE コードモデルライブラリを使用し、独立したネイティブソルバープロセスを実行 | アナログ SPICE および XSPICE コース |
| ブラウザー | 別個の Web ワーカー内で、WebAssembly にコンパイルされた ngspice を実行 | アナログ SPICE および互換性のあるアナログ動作モデル。このビルドには XSPICE は含まれません |

TinyCAD は環境に応じてバックエンドを選択します。同梱の例を使う場合、ngspice の実行ファイルを
探したり外部シミュレーターを選択したりする必要はありません。XSPICE の回路図にモデル定義を
含めることはできますが、デスクトップ版に付属するネイティブのコードモデルライブラリが必要です。
回路図をブラウザーにコピーしても、そのエンジン機能は追加されません。

## 回路図から結果まで
{: #from-drawing-to-result}

主な段階は次のとおりです。

1. **電気的接続を特定する。** TinyCAD は、ワイヤー、接合点、ネットラベルから、どのコンポーネントのピンが
   同じネットを共有しているかを判断します。ワイヤーの交差は、図面上で実際にネットが接続されていない限り、
   接続とはみなされません。一致するネットラベルは離れた点同士を接続しますが、ワイヤーの近くに描かれた
   テキストは接続しません。
2. **コンポーネント定義を展開する。** シミュレーション対象の各シンボルは SPICE テンプレートを提供します。
   TinyCAD は、その参照名、接続されたノード名、値を代入し、必要なデバイス定義またはサブサーキット定義を含めます。
3. **実験を追加する。** Simulation シートでは、解析、温度、パラメーター、モデルの添付、要求する信号を指定します。
   TinyCAD は回路を送信する前に、モデルの欠落、未解決のピン、参照名の重複など、検出可能な設定エラーを確認します。
4. **ngspice を実行する。** ソルバーは電圧、電流、その他要求された量を計算します。データと診断ログが返され、
   TinyCAD はそれらを、実行時の設定とエンジン識別情報に関連付けた取得データとして収集します。
5. **確認して測定する。** TinyCAD はチャート、数値データ、計算された測定値を表示します。たとえば、遮断周波数の測定値は
   AC データから算出されるもので、回路図に挿入される別のコンポーネントではありません。

このため、見た目が正しいだけでは不十分です。トランジスターにはモデルと正しいピン割り当てが必要であり、
また、現在のズームで端点が近く見えても、2 本のワイヤーは電気的に接続されていなければなりません。

## どのシンボルを使えばよいですか？
{: #which-symbols-should-i-use}

ツールバーの **パルス形アイコン**を開きます。ホバーテキストは **Simulation** です。
以下の説明にある **Simulation → …** は、このアイコンのメニューを意味します。

| 必要なもの | 場所 | 確認する項目 |
| --- | --- | --- |
| 抵抗器、コンデンサー、インダクター、ダイオード、LED、NPN/PNP トランジスター、または 741 オペアンプ | **Simulation → SPICE components**、または **SPICE essentials** ライブラリー | 値、極性、電源、モデルの前提条件 |
| 独立電圧／電流刺激 | **Simulation → SPICE → Insert Source** | ソースの種類、信号形状、単位、接続方向 |
| 基準ノード | **Simulation → SPICE → Insert Ground** | 電気的に接続すること。SPICE の基準ノードは `0` |
| 電圧の観測 | SPICE サブメニューの **Insert Probe** または **Insert Differential Probe** | 単端電圧はグラウンド基準です。差動プローブは端子間の電圧を測定します |
| 分岐電流の観測 | **Simulation → SPICE → Insert Current Probe** | 直列に挿入し、正方向を確認します |
| 従属電源 | **Simulation → SPICE → Insert Controlled Source** | 制御端子、出力端子、利得／相互コンダクタンス |
| ベンチ型計測器 | **Simulation → Lab Equipment** | オシロスコープ、マルチメーター、ファンクションジェネレーター、ベンチ電源の設定。負荷と制限が重要です |
| 通常のモデル化されたロジック | **Digital logic** ライブラリー | これらの設定可能で移植性のある SPICE モデルは、イベント駆動型の XSPICE の例とは異なります。電源ピンとモデルのプロパティを確認してください |
| イベント駆動型 XSPICE ロジック | 埋め込みの **XSPICE and digital tutorial** の例 | デスクトップ版を使い、モデル内のアナログ／デジタルブリッジを維持してください |

SPICE essentials ライブラリーには、一般的なデバイスの設定済みサンプルが用意されています。
汎用トランジスターや 741 型モデルは学習に便利ですが、そのシミュレーション動作が、特定メーカーの
部品の仕様と自動的に一致するわけではありません。アンプの各章では、元の `AMP.DSN` デバイスの代わりに
使用した汎用モデルについて明記しています。

別のライブラリーにあるシンボルは、図面専用の場合があります。配置したシンボルを選択し、プロパティの
**SPICE** タブを確認してください。有効な SPICE テンプレートと、そのテンプレートが参照するモデル定義が
必要です。一致する名前、パッケージ、図があっても、そうした定義が追加されるわけではありません。同様に、
`VCC` というラベルはネット名を指定するだけで、電源電圧は作りません。そのネットに実際の電源を接続してください。

## 既存の実験を実行する
{: #run-an-existing-experiment}

1. **Open Example → SPICE tutorial → divider → Open Drawing** を選びます。
2. **Simulation** シートを選択します。**Setup** の下に、保存された解析として
   **Measure DC — Operating Point** が設定されています。回路には 5 V 電源と 1 kΩ の抵抗器が 2 個使われています。
3. **Run** を選びます。チャートパネルが隠れている場合は **Simulation → Show charts** を使います。
4. `in`、`out`、`v1#branch` を確認します。それぞれ **5 V**、**2.5 V**、
   **−2.5 mA** となるはずです。電源電流は正端子に流れ込む方向を正と定義するため、ここでは電力を供給する電源の電流は負になります。
5. 回路シートで R2 を `2k` に変更して、再度実行します。OUT はおよそ **3.333 V** になるはずです。
   以前に保持された取得データは、以前の回路を示すままです。値を変更しても、その結果が書き換わることはありません。

![RC AC 解析と遮断周波数の結果を示す TinyCAD の Simulation シート](/v4/images/simulation-tutorials/spice/tinycad-ac-setup.png)

このアプリケーションのスクリーンショットは、埋め込み例 **rc-ac** の **Setup** ビューを示しています。
この 1 kΩ/1 µF フィルターの遮断周波数は約 **159.15 Hz** です。これを開いて、分圧器の単一 DC 動作点と
周波数領域の実験を比較してください。

**Run** は、選択した解析による有限時間の取得を開始します。**Stop** はソルバーを停止し、受理済みのサンプルを保持します。
それらのサンプルは部分的な結果であり、要求した時間が完了した証拠ではありません。これらのビルドでは、
一時停止／再開や、無期限に実行されるソルバーは利用できません。**History** で以前の実行を確認し、
**Diagnostics** でソルバーログを読みます。

デモについては、[分圧器を開いて実行し、変更する](/v4/videos/simulation-tutorials/spice/first-run.mp4)
および [AC 応答と遮断周波数](/v4/videos/simulation-tutorials/spice/ac-response.mp4) をご覧ください。どちらも、実際のデスクトップ版の操作部、
完了したネイティブ取得データ、数値結果を字幕付きで示しています。

## 初めてのシミュレーションを作成する
{: #build-your-own-first-simulation}

**Simulation → SPICE components** から抵抗器を 2 個配置し、**Insert Source** で電源を、
**Insert Ground** でグラウンドを配置します。分圧器になるように並べます。電源の正極を R1 に、
R1 を R2 に、R2 を電源の負極およびグラウンドに接続します。両方の抵抗器を
`1k` に設定し、電源を 5 V DC に設定して、電源のネットに `IN`、
中点に `OUT` というラベルを付けます。
R1、R2、V1 のように、各コンポーネントに一意の参照名が付いていることを確認します。

**Simulation → Simulate** を選択して Simulation シートを作成します。
**Setup** の下で **Measure DC — Operating Point** を選び、**Run** を実行します。
埋め込みの分圧器と同じ値が得られるはずです。失敗する場合は、接続、電源設定、SPICE プロパティを
動作するサンプルと比較してください。

過渡実験を行うには、**Over time — Transient** を選び、継続時間と最大ステップを設定して、
時間変化する電源を設定します。AC 解析では、**Frequency response — AC** を選び、周波数範囲と
ディケードあたりの点数を設定し、入力電源にゼロ以外の **AC amplitude**（通常は 1 V）を指定します。
正弦波の周波数や過渡振幅は、AC スイープの設定にはなりません。TinyCAD では、DC スイープ、ノイズ、
伝達関数、極零点解析も利用できます。それぞれが役立つ場面については、前の章で説明しています。

## 生成された SPICE を確認してモデルを追加する
{: #inspect-the-generated-spice-and-add-models}

分圧器を実行した後、**Diagnostics → Generate circuit text** を開きます。
重要な行は次のようになります。TinyCAD は、温度と保存する信号の指示も追加します。

```spice
R1 IN OUT 1k
R2 OUT 0 1k
V1 IN 0 DC 5 AC 0 0
.op
.end
```

`R1 IN OUT 1k` は、ノード IN と OUT の間にある 1 kΩ の抵抗器を意味します。`0` は
基準ノードです。このテキストでは、接続と電源の極性が明示されます。ネットリストを個別に確認または実行する場合は、
**Export circuit** を使います。TinyCAD の Simulation シートが `.op`、`.tran`、
`.ac` などの解析コマンドを管理します。これらや `.end` を、コンポーネントの
SPICE プロパティに貼り付けないでください。

TinyCAD のカタログにある部品については、[同梱 SPICE モデル](../Bundled-SPICE-Models/) を使って定義を選び、ピン割り当てを確認します。
Custom 定義で外部ファイルが必要な場合は、**Setup → SPICE models** を展開します。
`.lib`、`.cir`、`.mod` のいずれかのファイルを選ぶか、ファイル名とモデルテキストを入力します。
どちらの場合も、**Save model** を選んで添付します。`device.lib` のような単純なファイル名を使います。
次に、適切なデバイスまたは `.SUBCKT` をインスタンス化するよう、シンボルの SPICE テンプレートを設定し、
必要に応じてプロローグに `.include device.lib` を記述するなどして、添付ファイルを含めます。
ファイルを添付しただけでは、シンボルへの割り当ては行われません。

モデルの端子順は、ページ上での見かけの位置ではなく、シンボルの **ピン番号**と照合してください。
3 端子トランジスタモデルとメーカーのサブサーキットでは、ノード順が異なる場合があります。
ネストされたモデル参照も確認してください。インクルードするファイルも Simulation シートに添付する必要があります。
モデル定義と添付ファイルは、保存した図面とともに保持されます。

TinyCAD がサポートするのは、埋め込みモデルテキストであり、任意の ngspice コマンドスクリプトや外部実行モジュールではありません。
`.control` ブロック、シェルコマンド、外部モジュールの読み込み、ファイルを参照する刺激／モデルは、このワークフローでは使用できません。
サポートされている電源設定と解析を使うか、回路をエクスポートして、別途コマンドラインで ngspice を使った実験を行ってください。
別の SPICE 方言向けに記述されたメーカーのモデルは、ngspice が受け付けるように変更が必要な場合があります。

## デジタルシミュレーションについて
{: #how-digital-simulations-fit-in}

デスクトップ版で **XSPICE and digital tutorial → logic-buffer** を開きます。
その X1 モデルには、アナログからデジタルへのブリッジ、イベント駆動型バッファー、
デジタルからアナログへのブリッジが含まれています。通常の電源がアナログ入力を駆動し、
ブリッジによってロジック状態を TinyCAD のチャート上の電圧として確認できます。

![埋め込み XSPICE バッファーの計算された入力と出力](/v4/images/simulation-tutorials/xspice/logic-buffer-results.png)

保存された過渡解析を実行します。0～5 V、周期 1 µs のパルスと、有限の立ち上がり／立ち下がり時間を持つ、
約 20 ns 遅延した出力遷移が得られるはずです。遅延を確認するには拡大表示します。
この図には、例の実際のソルバー結果がプロットされています。

モデルのデジタルノードは、通常の電圧ノードではありません。ブリッジのしきい値と不定状態の表現は、
意図的に選ばれたモデリング方法です。アナログ SPICE 式から構成した動作ゲートは、チャート上では似て見える場合がありますが、
異なるシミュレーション方式を使っています。ブリッジ、タイミング、ストレージ、混合信号回路については、
[XSPICE 概要](/v4/XSPICE-Tutorial-01/) に進んでください。

## 保存、比較、トラブルシューティング
{: #save-compare-and-troubleshoot}

埋め込み例の編集可能なコピーを保持するには、**Save As** で実験を保存します。
TinyCAD では取得データを図面とともに保持できます。**Save without
results** を使うと、回路と設定は保持しつつ、保存済みの結果は省略されます。
追加の解析が必要な場合は、**Data** エクスポートで CSV、JSON、または SPICE raw データを出力します。
使用した取得データ、モデル、測定ウィンドウを記録してください。

| 症状 | 最初に確認すること |
| --- | --- |
| SPICE 情報がない | モデル化されたシンボルを使うか、その SPICE タブを設定します |
| モデルまたはサブサーキットがない | モデル名、添付ファイル、include 文、端子順 |
| 回路が浮いている、またはグラウンドがない | SPICE グラウンドが接続されていること、および適切な DC 帰路 |
| 電源ラベルはあるが電源電圧がない | ラベル付きネットに電圧源またはベンチ電源を接続します |
| AC 応答が空／ゼロ | 入力の AC 振幅と選択した信号 |
| ブラウザーで XSPICE モデルを使用できない | TinyCAD デスクトップ版で例を実行します |
| プロットが編集後の値と一致しない | 再実行して、新しい取得データを選択します |
| 収束エラーまたは波形が未完了 | Diagnostics を読み、回路を単純化し、刺激のエッジ、タイムステップ、モデルの妥当性を確認します |

デバイスとモデルの意味については、[ngspice マニュアル](https://ngspice.sourceforge.io/docs.html) がリファレンスです。
TinyCAD の操作機能によって、統合ワークフローから利用できる機能が決まります。

## レッスン回路をダウンロードする
{: #download-the-lesson-circuits}

同じ例は **Open Example** からすでに利用できます。独立したコピーが必要な場合は、`.dzn` の図面をダウンロードし、
TinyCAD で **File → Open** を使います。対応する `.cir` は、確認用または互換性のある外部シミュレーター用の SPICE テキストであり、
TinyCAD の図面ではありません。XSPICE 回路を新たに実行するにはデスクトップ版が必要です。

| 例 | 図面 | ネットリスト |
| --- | --- | --- |
| divider | [TinyCAD 図面](/v4/examples/simulation-tutorials/spice/divider.dzn) | [SPICE テキスト](/v4/examples/simulation-tutorials/spice/divider.cir) |
| logic-buffer | [TinyCAD 図面](/v4/examples/simulation-tutorials/xspice/logic-buffer.dzn) | [SPICE テキスト](/v4/examples/simulation-tutorials/xspice/logic-buffer.cir) |
