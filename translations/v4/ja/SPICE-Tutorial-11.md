# 11. TinyCADによるSPICEの実装
{: #how-tinycad-implements-spice}

[前へ: 設計の検討](/v4/SPICE-Tutorial-10/) · [目次](/v4/Simulation-Tutorials/) · [XSPICE講座](/v4/XSPICE-Tutorial-01/)

TinyCADは回路図エディター、シミュレーション設定、計測器、グラフ、測定機能を提供します。その下で回路を解くエンジンが**ngspice**です。TinyCADで実験を作図・設定すると、TinyCADがSPICE回路テキストに変換してngspiceを実行し、返された結果を表示します。

この章の例はTinyCADに同梱されています。**Open Example →
SPICE tutorial**を選び、**divider**または**rc-ac**を選択してから、**Open Drawing**を選びます。デジタルのデモでは、**Open Example → XSPICE and digital tutorial →
logic-buffer → Open Drawing**を使用します。チュートリアルやモデルをダウンロードする必要はありません。

## SPICE、ngspice、XSPICE
{: #spice-ngspice-and-xspice}

SPICEでは、回路を部品、接続されたノード、数学的なデバイスモデルで表現します。動作点解析では、それらのDC方程式を解きます。過渡解析では、シミュレーション時間に沿った回路の動作を追跡します。AC解析では、バイアス点を中心に回路を線形化し、小信号周波数応答を計算します。したがって、解析の選択は実験の定義の一部です。

ngspiceは、Berkeley SPICEを起源とするオープンソースの混合信号回路シミュレーターです。TinyCADはエンジンを同梱しているため、別のコマンドラインシミュレーターをインストールして実行する必要はありません。これらのチュートリアルの認定に使用されたエンジンは**ngspice 47**です。実行の**Diagnostics**ビューで、バックエンドとビルドを確認できます。上流プロジェクトの背景については、[ngspice公式概要](https://ngspice.sourceforge.io/presentation.html)
を参照してください。

**XSPICEはngspiceに統合された拡張機能**であり、別途起動するアプリケーションではありません。機能的なアナログブロックや、アナログソルバーとイベントが連携するデジタルロジックなどのコードモデルを追加します。そのため、デジタル状態の変化が同じシミュレーション内のアナログ回路に影響を与えられます。この違いについては、[XSPICE公式紹介](https://ngspice.sourceforge.io/xspice.html)
で説明されています。

| TinyCAD環境 | エンジンの実行方法 | 使用する例 |
| --- | --- | --- |
| デスクトップ | 同梱のXSPICEコードモデルライブラリを使い、別のネイティブソルバープロセスとして実行 | アナログSPICEおよびXSPICE講座 |
| ブラウザー | ngspiceをWebAssemblyにコンパイルし、別のウェブワーカー内で実行 | アナログSPICEおよび互換性のあるアナログ動作モデル。このビルドにはXSPICEは含まれません |

TinyCADは環境に応じてバックエンドを選択します。同梱の例を使う際に、ngspiceの実行ファイルを探したり、外部シミュレーターを選択したりする必要はありません。XSPICEの回路図にモデル定義を含めることはできますが、デスクトップ版に付属するネイティブコードモデルライブラリは引き続き必要です。回路図をブラウザーにコピーしても、そのエンジン機能が追加されるわけではありません。

## 回路図から結果まで
{: #from-drawing-to-result}

主な段階は次のとおりです。

1. **電気的な接続を特定する。** TinyCADは、配線、接合点、ネットラベルから、どの部品ピンが同じネットを共有するか判断します。配線の交差は、回路図上で実際にネットが接続されていなければ、接続とはみなされません。一致するネットラベルは離れた点同士を接続しますが、配線の近くに描かれたテキストは接続しません。
2. **部品定義を展開する。** シミュレーション対象の各シンボルにはSPICEテンプレートが用意されています。TinyCADはその参照名、接続されたノード名、値を置き換え、必要なデバイスまたはサブサーキット定義を含めます。
3. **実験を追加する。** Simulationシートで解析、温度、パラメーター、モデル添付、要求する信号を指定します。TinyCADは回路を実行に渡す前に、モデルの不足、未解決のピン、重複した参照名など、検出可能な設定エラーを確認します。
4. **ngspiceを実行する。** ソルバーが電圧、電流、その他の要求された量を計算します。ソルバーはデータと診断ログを返し、TinyCADはそれらを、実行時の設定とエンジン情報に関連付けた取得データとして収集します。
5. **確認して測定する。** TinyCADはグラフ、数値データ、計算された測定値を表示します。たとえば、カットオフ周波数の測定値はACデータから算出され、回路図に挿入される別の部品ではありません。

この仕組みから、見た目が正しいだけでは不十分な理由がわかります。トランジスターにはモデルと正しいピン割り当てが必要です。また、ズーム倍率によって端点が近く見えても、2本の配線は電気的に接続されていなければなりません。

## どのシンボルを使えばよいですか？
{: #which-symbols-should-i-use}

**パルス形のアイコン**を開きます。カーソルを合わせると **Simulation** と表示されます。
以下の手順で、**Simulation → …** はこのアイコンのメニューを意味します。

| 必要なもの | 場所 | 確認する項目 |
| --- | --- | --- |
| 抵抗、コンデンサー、インダクター、ダイオード、LED、NPN/PNPトランジスター、741オペアンプ | **Simulation → SPICE components**、または**SPICE essentials**ライブラリー | 値、極性、電源、モデルの前提条件 |
| 独立した電圧／電流の刺激源 | **Simulation → SPICE → Insert Source** | ソースの種類、信号形状、単位、接続方向 |
| 基準ノード | **Simulation → SPICE → Insert Ground** | 電気的に接続します。SPICEの基準ノードは`0`です |
| 電圧の観測 | SPICEサブメニューの**Insert Probe**または**Insert Differential Probe** | 単端電圧はグラウンド基準です。差動プローブは端子間を測定します |
| 分岐電流の観測 | **Simulation → SPICE → Insert Current Probe** | 直列に挿入し、正方向を確認します |
| 従属電源 | **Simulation → SPICE → Insert Controlled Source** | 制御端子、出力端子、利得／相互コンダクタンス |
| ベンチ型計測器 | **Simulation → Lab Equipment** | オシロスコープ、マルチメーター、ファンクションジェネレーター、ベンチ電源の設定。負荷と制限に注意してください |
| 通常のモデル化されたロジック | **Digital logic**ライブラリー | これらの設定可能で移植性のあるSPICEモデルは、イベント駆動型のXSPICE例とは異なります。電源ピンとモデルプロパティを確認してください |
| イベント駆動型XSPICEロジック | 組み込みの**XSPICE and digital tutorial**の例 | デスクトップ版を使用し、モデル内のアナログ／デジタル間ブリッジを維持してください |

SPICE essentialsライブラリーには、一般的なデバイスの設定済みサンプルが用意されています。汎用トランジスターや741形式のモデルは学習に役立ちますが、そのシミュレーション動作が特定メーカー製品の仕様を自動的に反映するわけではありません。アンプの各章では、元の`AMP.DSN`デバイスの代わりに使用した汎用モデルについて明記しています。

別のライブラリーにあるシンボルは、作図専用の場合があります。配置したシンボルを選択し、プロパティの**SPICE**タブを確認してください。有効なSPICEテンプレートと、そのテンプレートが参照するモデル定義が必要です。名前、パッケージ、図柄が一致していても、それらの定義が追加されるわけではありません。同様に、`VCC`というラベルはネット名を付けるだけで、電源電圧を生成するものではありません。そのネットに実際の電源を接続してください。

## 既存の実験を実行する
{: #run-an-existing-experiment}

1. **Open Example → SPICE tutorial → divider → Open Drawing**を選びます。
2. **Simulation**シートを選択します。**Setup**の下に、保存済みの解析**Measure DC — Operating Point**があります。この回路は5 V電源と2つの1 kΩ抵抗を使用しています。
3. **Run**を選びます。グラフパネルが非表示の場合は、**Simulation → Show charts**を選びます。
4. `in`、`out`、`v1#branch`を確認します。それぞれ**5 V**、**2.5 V**、**−2.5 mA**になるはずです。電源電流は正端子に流れ込む向きが正として定義されるため、電力を供給している電源の電流はここでは負になります。
5. 回路シートでR2を`2k`に変更して、再度実行します。OUTは約**3.333 V**になるはずです。以前の取得データが保持されている場合、それは変更前の回路の結果を示します。値を変更しても、その結果は書き換わりません。

![RC AC解析とカットオフ結果を表示するTinyCADのSimulationシート](/v4/images/simulation-tutorials/spice/tinycad-ac-setup.png)

このアプリケーションのスクリーンショットは、もうひとつの組み込み例**rc-ac**の**Setup**ビューを示しています。1 kΩ／1 µFフィルターのカットオフ周波数は約**159.15 Hz**です。これを開いて、周波数領域の実験とdividerの単一DC点を比較してください。

**Run**は選択した解析で有限時間のデータ取得を開始します。**Stop**はソルバーを終了し、受け入れ済みのサンプルを保持します。これらのサンプルは部分的な結果であり、要求された時間が完了したことを示すものではありません。これらのビルドでは、一時停止／再開や無期限に実行されるソルバーは使用できません。**History**で以前の実行を確認し、**Diagnostics**でソルバーログを読んでください。

デモについては、[分圧回路を開いて実行・変更する](/v4/videos/simulation-tutorials/spice/first-run.mp4)
および[AC応答とカットオフ周波数](/v4/videos/simulation-tutorials/spice/ac-response.mp4)をご覧ください。どちらも、実際のデスクトップ版のコントロール、完了したネイティブ取得データ、数値結果を字幕付きで示しています。

## 最初のシミュレーションを作成する
{: #build-your-own-first-simulation}

**Simulation → SPICE components**から抵抗を2つ配置し、**Insert Source**でソース、**Insert Ground**でグラウンドを配置します。分圧回路になるよう配置します。ソースの正側をR1に、R1をR2に、R2をソースの負側およびグラウンドに接続します。両方の抵抗を`1k`に設定し、ソースを5 V DCに設定して、電源に`IN`、中点に`OUT`というラベルを付けます。R1、R2、V1のように、すべての部品に一意の参照名を付けてください。

**Simulation → Simulate**を選択してSimulationシートを作成します。**Setup**の下で**Measure DC — Operating Point**を選択し、**Run**を選びます。組み込みのdividerと同じ値が得られるはずです。失敗する場合は、接続、ソース設定、SPICEプロパティを、動作する例と比較してください。

過渡解析では、**Over time — Transient**を選択し、継続時間と最大ステップを設定して、時間変化するソースを構成します。AC解析では、**Frequency response — AC**を選び、周波数範囲とディケード当たりの点数を設定し、入力ソースの**AC amplitude**をゼロ以外（通常は1 V）にします。ソースの正弦波周波数と過渡解析の振幅は、AC掃引の設定にはなりません。TinyCADでは、DC掃引、ノイズ、伝達関数、極零点解析も使用できます。それぞれの用途については前の章を参照してください。

## 生成されたSPICEを確認してモデルを追加する
{: #inspect-the-generated-spice-and-add-models}

dividerの実行後、**Diagnostics → Generate circuit text**を開きます。重要な行は次のようになります。TinyCADは温度と保存信号のディレクティブも追加します。

```spice
R1 IN OUT 1k
R2 OUT 0 1k
V1 IN 0 DC 5 AC 0 0
.op
.end
```

`R1 IN OUT 1k`は、ノードINとOUTの間にある1 kΩの抵抗を意味します。`0`は基準ノードです。このテキストで接続とソースの極性が明確になります。ネットリストを個別に確認または実行する必要がある場合は、**Export circuit**を使用します。TinyCADのSimulationシートで`.op`、`.tran`、`.ac`などの解析コマンドを管理します。これらや`.end`を部品のSPICEプロパティに貼り付けないでください。

追加のデバイスモデルを使用するには、**Setup → SPICE models**を展開します。`.lib`、`.cir`、`.mod`のファイルを選択するか、ファイル名とモデルテキストを入力します。どちらの場合も、**Save model**を選択して添付します。`device.lib`のような簡潔なファイル名を使用してください。次に、シンボルのSPICEテンプレートを設定して、適切なデバイスまたは`.SUBCKT`をインスタンス化し、必要に応じて、たとえばプロローグに`.include device.lib`を記述して添付ファイルを含めます。ファイルを添付しただけでは、シンボルへの割り当ては行われません。

モデルの端子順序は、ページ上でのピンの見かけ上の位置ではなく、シンボルの**ピン番号**と照合してください。3端子トランジスタモデルとメーカー製サブサーキットでは、ノードの順序が異なる場合があります。入れ子になったモデル参照も確認してください。インクルードされるファイルもSimulationシートに添付する必要があります。モデル定義と添付ファイルは、保存した回路図とともに保持されます。

TinyCADがサポートするのは、埋め込みモデルテキストであり、任意のngspiceコマンドスクリプトや外部実行可能モジュールではありません。`.control`ブロック、シェルコマンド、外部モジュールの読み込み、ファイルを使用する刺激源／モデルは、このワークフローでは使用できません。サポートされているソースコントロールと解析を使用するか、別個のコマンドラインngspice実験用に回路をエクスポートしてください。別のSPICE方言向けに書かれたベンダーモデルは、ngspiceで受け入れられるように調整が必要な場合があります。

## デジタルシミュレーションの位置付け
{: #how-digital-simulations-fit-in}

デスクトップ版で**XSPICE and digital tutorial → logic-buffer**を開きます。そのX1モデルには、アナログからデジタルへのブリッジ、イベント駆動型バッファー、デジタルからアナログへのブリッジが含まれています。通常のソースがアナログ入力を駆動し、ブリッジによりロジック状態をTinyCADのグラフ上で電圧として確認できます。

![組み込みXSPICEバッファーの計算された入力と出力](/v4/images/simulation-tutorials/xspice/logic-buffer-results.png)

保存された過渡解析を実行します。周期1 µsの0～5 Vパルスが得られ、出力の遷移は約20 ns遅延し、有限のエッジを持つはずです。拡大して遅延を確認してください。この図は、例から得られた実際のソルバー結果をプロットしています。

モデルのデジタルノードは通常の電圧ノードではありません。ブリッジのしきい値と未定義状態の表現は、意図的なモデル化上の選択です。アナログSPICE式で構成した動作ゲートはグラフ上では似て見える場合がありますが、異なるシミュレーション方式を使います。ブリッジ、タイミング、記憶素子、混合信号回路については、[XSPICEの概要](/v4/XSPICE-Tutorial-01/)を続けて参照してください。

## 保存、比較、トラブルシューティング
{: #save-compare-and-troubleshoot}

組み込み例の編集可能なコピーを保持するには、実験を**Save As**で保存します。TinyCADは取得データを回路図とともに保持できます。**Save without results**を選ぶと、回路と設定は保持されますが、保存された結果は除外されます。さらに分析する必要がある場合は、**Data**からCSV、JSON、SPICE rawデータをエクスポートします。使用した取得データ、モデル、測定ウィンドウを記録してください。

| 症状 | 最初に確認する項目 |
| --- | --- |
| SPICE情報がない | モデル化されたシンボルを使うか、SPICEタブを設定する |
| モデルまたはサブサーキットがない | モデル名、添付ファイル、インクルード文、端子順序 |
| 回路が浮いている、またはグラウンドがない | 接続されたSPICEグラウンドと適切なDC帰路 |
| 電源ラベルはあるが電圧がない | 電圧ソースまたはベンチ電源をラベル付きネットに接続する |
| AC応答が空またはゼロ | 入力のAC振幅と選択した信号 |
| ブラウザーでXSPICEモデルが使用できない | TinyCADデスクトップ版で例を実行する |
| プロットが編集後の値と一致しない | 再実行して新しい取得データを選択する |
| 収束エラーまたは不完全な波形 | Diagnosticsを読み、回路を簡素化して、刺激源のエッジ、時間刻み、モデルの妥当性を確認する |

デバイスとモデルの動作については、[ngspiceマニュアル](https://ngspice.sourceforge.io/docs.html)が参考資料です。TinyCADのコントロールにより、統合されたワークフローで利用できる機能が決まります。
