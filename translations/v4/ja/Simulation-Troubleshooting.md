# シミュレーションのトラブルシューティング
{: #simulation-troubleshooting}

設定を変更する前に、取得ステータスと診断出力を確認してください。**実行に失敗した場合**、**有効な実行結果だが動作が想定外の場合**、**選択した結果から測定値を取得できない場合**を区別してください。それぞれ確認すべき項目が異なります。

## シミュレーションが開始しない
{: #the-simulation-will-not-start}

| 症状 | 確認事項 |
| --- | --- |
| グラウンドがない／回路が浮いている | 電源シンボルまたは値が **0** のラベルを接続します。別個のGNDラベルが自動的にノード0になるわけではありません。電源の戻り線と絶縁されたサブサーキットを確認してください。 |
| コンポーネントモデルがない | シンボルを選択して **SPICE** を確認します。モデル付きのライブラリ部品を使うか、[バンドル定義またはカスタム定義を割り当て](../Bundled-SPICE-Models/)します。 |
| 検索に一致するモデルがない | 検索をクリアするか、部品の別名またはデバイスファミリーを試します。SPICE essentialsシンボルには、検証済みのモデルのみが表示されます。 |
| 属性がない、またはピン割り当てが無効 | コンポーネントのSPICEプロパティと、実際のモデルの端子順序を確認します。インスタンスの上書き設定によって既定値が変更されることがあります。 |
| モデル／インクルードファイルが見つからない | 対応する論理ファイル名を使用して、モデルテキストとその依存ファイルをSimulationシートに添付します。ローカルの絶対パスやWeb URLから自動的に取得されることはありません。 |
| コンポーネントに解析ディレクティブが含まれている | コンポーネント属性から、旧式の`.op`、`.tran`、`.ac`、`.end`、および実行制御テキストを削除します。解析設定は統合Simulationシートで管理します。 |
| ブラウザーでXSPICEモデルを利用できない | 新たにネイティブ実行するには、Desktopで図面を開きます。ブラウザーでも保存済みの結果を確認できます。 |
| ソースまたは範囲が無効 | 波形フィールド、単調増加するPWL時刻、開始／終了値、掃引方向、および正の周波数／時間の値を確認します。 |

## 結果が正しくない、またはソルバーが収束しない
{: #a-result-is-wrong-or-the-solver-does-not-converge}

**まず回路を確認してください。** 配線端点を越えて伸びた線や未使用のソケットによって、意図しない接続が作成されることがあります。T字接続、実際のピン先端、ネットラベル、非表示の電源を確認してください。電流プローブやメーターを電源の両端に接続すると、短絡する可能性があります。生成されたネットリストを使って、シミュレーターに渡された内容を確認してください。

モデルの向きと順序を確認します。ダイオードの極性、BJTのコレクタ／ベース／エミッタ、オペアンプの電源ピン、サブサーキットのピン順序を確認してください。意味のある一意な参照名を使い、掃引／ノイズ／伝達特性の設定で指定したソース参照が意図したソースを指していることを確かめます。

ACを調べる前に、Operating PointでDCバイアスを確認してください。理想電源のループ、浮遊ノード、急峻な理想遷移、妥当でないモデルパラメーターは、回路の解析を困難または不可能にすることがあります。それらが実際の実験を表す場合は、物理的に妥当な抵抗値や有限のエッジ時間を追加してください。数値オプションを変更する前に、複雑な回路を、問題が発生する最小の部分に切り分けます。

数値の接尾辞を確認してください。**SPICEテキストの1Mは1ミリ単位であり、1メガ単位ではありません**。メガには`1Meg`を使用します。温度、ソースのDC値、過渡解析／AC設定をそれぞれ別に確認してください。ソースの過渡振幅が自動的に小信号AC振幅になるわけではありません。

## 波形が途中までしか表示されない
{: #the-waveform-looks-incomplete}

- 起動時の過渡状態が収束していない場合や、必要な周期が実行範囲外にある場合は、過渡解析の時間を延長します。
- 高速エッジや短いパルスを捉えるには、最大刻み幅を小さくします。表示を拡大しても、欠落したサンプルは復元できません。
- 選択した設定、取得データ、結果プロット、凡例の表示状態、単位、軸の範囲を確認します。
- AC解析では、鋭い共振付近に十分な点数を設定し、正しい入力／出力比を使用します。
- 実行が停止または失敗した場合は、実際にデータが得られているか確認します。部分的なトレースは実験の完了を意味しません。

## チャートまたはプローブの読み取り値が古い
{: #charts-or-probe-readings-are-stale}

配線、値、モデルテキスト、または設定を編集した場合は、もう一度 **実行（Run）** する必要があります。保存された取得データは、元の入力条件を記録したものです。履歴の選択によって図面が元に戻るわけではありません。付属のチュートリアルは、自分で何かを実行する前でも、保持された参照結果を表示することがあります。

パネルが非表示の場合は、**Simulation → チャートを表示（Show charts）**、またはDesktopの **View → Chartsを表示（Show Charts）** を選択します。自動プローブのチャートを削除すると、明示的に再追加するまで削除されたままになります。チャートをポップアウトした場合、閉じるとパネルに戻ります。

## 測定値を取得できない
{: #a-measurement-is-unavailable}

信号のバインド、単位、ウィンドウ、しきい値、明示的な初期／最終レベルを確認します。タイミング測定には、完全な交差点または周期が必要です。整定測定は、宣言した最終帯域内で終了する必要があります。遮断周波数の測定には、要求された交差点とゲイン基準が必要です。帯域幅の測定には2つの交差点が必要です。掃引の境界にある共振は確定できません。サポートされていないデバイス電流／電力ベクトルは推測されません。

取得できない要件は合格ではありません。スタディレポートには条件と失敗ステータスを含め、収束しなかった公差ケースも表示したままにしてください。評価可能な要件がないスタディでは、歩留まりを推定できません。

## 調査結果の保存と再現
{: #saving-and-reproducing-an-investigation}

図面、モデル添付ファイル、解析設定、ソース設定、温度、および関連する取得データをまとめて保持してください。数値結果を含めずに保存した場合や、ファイルサイズを小さくするために数値結果を削除した場合は、チャートを復元するために再実行してください。保持されたスカラー値／レポートのスナップショットから、欠落した波形配列を再作成することはできません。

再現可能なレポートには、モデルの前提、エンジン、測定ウィンドウ、条件を記載します。シミュレーター言語に関する問題を切り分ける際は、[チュートリアルの期待値](../Simulation-Tutorials/)と公式の[ngspiceマニュアル](https://ngspice.sourceforge.io/docs.html)を比較してください。
